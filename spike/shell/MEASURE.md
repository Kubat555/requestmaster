# Пробник окна — как провести замеры (Task 5, шаги 2–4)

Всё запускается из корня репозитория `C:\NSK\MyPostman`. Окно уже собрано; если нужно пересобрать:

```powershell
cd spike\shell
npm install
npm run tauri build
```

Готовый exe: `spike\shell\src-tauri\target\release\requestmaster-spike.exe`.
Установщик: `spike\shell\src-tauri\target\release\bundle\nsis\RequestMaster Spike_0.1.0_x64-setup.exe`.
Для замеров ставить его не нужно — скрипт и шаги ниже работают с exe напрямую.

## Шаг 2. Холодный запуск и память

1. Закройте окно RequestMaster Spike, если оно открыто.
2. Запустите:

   ```powershell
   powershell -ExecutionPolicy Bypass -File spike\shell\measure-start.ps1
   ```

   Скрипт 10 раз открывает и закрывает окно (около 30 секунд). По каждому запуску он печатает строку,
   в конце — три итоговые строки:
   - `start (in-app, ms since main)` — сколько миллисекунд прошло от первой строки `main` до первой
     отрисовки окна (это число пишет само приложение);
   - `start (wall, launch -> ready file)` — то же, но от команды запуска до появления файла готовности:
     включает загрузку exe и библиотек, то есть ближе к тому, что видит человек;
   - `memory (app + its WebView2, MB)` — сумма рабочей памяти процесса приложения и всех его процессов
     `msedgewebview2.exe`, через 1 секунду после готовности.
3. Запишите медиану и максимум для всех трёх строк. Цель спецификации — холодный запуск ≤ 1000 мс
   (предлагаю сравнивать с ней строку `wall`, она честнее).
4. Первый запуск после перезагрузки отдельно: перезагрузите компьютер, дождитесь, пока система
   успокоится (1–2 минуты), и выполните один прогон:

   ```powershell
   powershell -ExecutionPolicy Bypass -File spike\shell\measure-start.ps1 -Runs 1
   ```

   Запишите эти три числа отдельно — как «первый запуск после перезагрузки».

## Шаг 3. Замеры в окне

Откройте `spike\shell\src-tauri\target\release\requestmaster-spike.exe` двойным щелчком.

**Большие ответы.** В таблице «1. Большой ответ» 16 кнопок: размер (1 / 5 / 10 / 20 МБ) × формат
(pretty — с отступами, minified — в одну строку) × способ передачи (строка — обычный JSON-ответ команды,
байты — сырые байты без JSON-обёртки). Для каждой кнопки:

1. Нажмите кнопку **два раза** подряд (дождитесь окончания первого). Первое нажатие для пары
   «размер · формат» включает генерацию данных в Rust — в результатах оно помечено `*`. Записывайте
   числа второго нажатия.
2. Из таблицы «3. Результаты» запишите:
   - «Передача, мс» — от вызова команды до получения данных в JavaScript;
   - «Декодирование байтов, мс» — только для «байты»: перевод байтов в текст;
   - «Готовность редактора, мс» — от передачи текста редактору до первой отрисовки документа.
3. Сразу после замера щёлкните в поле «2. Отзывчивость ввода» и напечатайте пару слов. Рядом видно
   задержку последней клавиши и максимальную. Запишите максимум и ответ «ввод отзывчивый: да/нет»
   (на глаз: буквы появляются сразу, без рывков; ориентир — максимум до 100 мс).
   Это число отвечает только на вопрос «ввод отзывчивый: да/нет». С целью спецификации «отклик ≤ 16 мс» его
   сравнивать нельзя: поле меряет «нажатие → следующий кадр», что даёт 0–17 мс даже в простое.

Таблица для записи (по одной строке на кнопку):

| Размер | Формат | Передача | Передача, мс | Декодирование, мс | Редактор, мс | Макс. задержка ввода, мс | Ввод отзывчивый |
|---|---|---|---|---|---|---|---|
| 1 МБ | pretty | строка | | — | | | |
| 1 МБ | pretty | байты | | | | | |
| … | | | | | | | |

**SQLite.** Нажмите «Проверить db_roundtrip». Должно быть написано «совпадает», а путь к файлу — внутри
`%LOCALAPPDATA%` (ожидается `C:\Users\<вы>\AppData\Local\kg.nsk.requestmaster.spike\spike.db`). Проверьте,
что файл действительно там лежит. Запишите: строка без искажений — да/нет, путь.

## Шаг 4. Вывод порога

- **Порог «показывать целиком»** — наибольший размер, при котором и pretty, и minified (хотя бы одним
  способом передачи) дают «Редактор, мс» ≤ 300 и отзывчивый ввод.
- **Способ передачи** — на этом пороге сравнить «строка» и «байты»: для строки — «Передача», для байтов —
  «Передача» + «Декодирование». Выбирается тот, где сумма меньше.

Запишите оба решения.
